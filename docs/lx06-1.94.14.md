# LX06 1.94.14 同版本适配与验证

本次更新补充 **小爱音箱 Pro（LX06）1.94.14** 的构建输入校验和实机记录，不是首次增加 LX06 支持。当前仓库已有 LX06 的 ALSA、音频库补丁和构建 workflow；原固件下载说明列出的是 1.94.13。

**不适用于 OH2P 或其他固件版本，不把 1.94.13 改名成 1.94.14。** 本文不提供个人预制固件、设备账户或 SSH 密码，也不声称已经创建了 GitHub Release。

## 固件输入

完整可机读信息：[LX06_1.94.14.json](../packages/client-patch/profiles/LX06_1.94.14.json)。

- 官方 OTA：`mico_all_ce7185fc5_1.94.14.bin`，43,478,680 字节。
- MD5：`b66fe108ee32afdfaf020cace7185fc5`。
- SHA-256：`38428e73499ad832dd42c13492b391aa369b9c41d69fd46106707e671a84e27f`。
- 原始 rootfs SHA-256：`bdcac4449491bfaa9b3960ee006fd6e4932a9dae4473736fc808564d5eab7439`。
- 音频库中 `hw:0,3\0` 的唯一偏移为 773628；等长替换成 `noop\0\0\0`。先校验库哈希，再检查唯一性和偏移，失败即停止。

这套构建复用仓库的 6 个文本补丁，不重复修改音频采集实现；补丁必须符合 profile 中的哈希，使用 `--fuzz=0`。无线初始化脚本允许完整上下文匹配的 5 行位置偏移，不允许模糊匹配。

## Linux / WSL 本地构建

需要 `python3`、`openssl`、`patch`、`bash`、`squashfs-tools` 以及 GNU `cp`。在 Linux 文件系统中解包；root 权限只用于保留 rootfs 所有权和设备节点。此入口不登录小米、不连接音箱、不执行 USB/SSH 或刷机命令。

从仓库根目录执行（把路径换成自己的绝对路径）：

```sh
# 如需下载，使用已知官方链接；下载后仍须校验完整摘要。
curl -fL 'https://cdn.cnbj1.fds.api.mi-img.com/xiaoqiang/rom/lx06/mico_all_ce7185fc5_1.94.14.bin' \
  -o /absolute/path/mico_all_ce7185fc5_1.94.14.bin

# 只检查输入，不解包、不生成固件；无需 root。
python3 packages/client-patch/src/build_verified.py \
  --ota /absolute/path/mico_all_ce7185fc5_1.94.14.bin \
  --output /absolute/path/verified-output-lx06 --check-only

# output 必须不存在。失败后的目录保留，改用新目录重试，不自动删文件。
sudo python3 packages/client-patch/src/build_verified.py \
  --ota /absolute/path/mico_all_ce7185fc5_1.94.14.bin \
  --output /absolute/path/verified-output-lx06
```

输出：`LX06_1.94.14_patched.squashfs`、`manifest.json` 和 **私密** `SSH-CREDENTIALS.json`。SSH root 密码每次构建随机生成；不要上传密码文件或包含该密码哈希的个人固件。

核验包括完整 OTA 摘要及 CRC32、型号版本、11 个预期变更、权限/所有者、脚本语法、xz/131072 块参数、40 MiB 分区上限、重新解包的完整树比较，以及同一次构建两次打包结果相同。每次生成的新密码使不同构建的镜像摘要不同；不是跨密码的位级一致性承诺。

2026-10-08 该入口实际离线重建通过，补丁镜像为 38,453,248 字节。新生成的镜像没有再次刷机，输出状态明确为 `deviceFlashed: false`。

测试：

```sh
python3 -m unittest discover -s packages/client-patch/tests -v
```

## 刷写与恢复边界

通过构建检查不等于所有同型号设备都验证安全。先核对真实机型、ROM、分区大小和备份；按[刷机教程](flash.md)操作。此次实测写的是 `system0`，启动的是 `boot0`。`identify` 的 `0-7-0-16` 是 USB 协议标识，不是 ROM 版本。

以完整传输和 `mwrite success` 判定写入成功，不只看程序退出码或扫描其他端口的失败行。断开 USB 后正常上电，先测试原生小爱，再 SSH 核验。`boot1` 只有在另一槽完整可启动时才是恢复入口；未验证之前不要把双槽机制当成不会变砖的保证。
